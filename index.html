About

I came up through Linux and cloud operations, then spent the last several years making delivery repeatable: infrastructure in code, a Kubernetes path people can use, and an on-call loop that feeds back into the design. The agentic work is the same job. A workflow that can call tools and retrieve knowledge still has to be provisioned, released, observed, and stopped.

If it needs a ticket, it is not a platform.

Engineers should provision, deploy, and roll back without waiting on me. Terraform, pipelines, and GitOps exist so the exception is rare, not so the happy path stays manual.

Autonomy is earned.

An agent gets tool access and memory after evaluation, guardrails, and a human gate exist. Deterministic release steps stay in charge. The model does not get a private way into production.

Incidents are design input.

A postmortem that only updates a runbook will happen again. The useful ones change the module, the pipeline, or the alert threshold.

Selected work

Platform

One way to stand an environment up

The estate spans AWS, Azure, and what is still on VMware and OpenStack. I treat that as one provisioning problem. Terraform holds the shape of the environment, including remote state and drift. Ansible holds configuration, patching, and the bootstrap that used to live in someone’s notes. Multi-AZ and recovery are part of the module, not a follow-up project. Cost shows up in the same review as the change, because a platform nobody can afford is not finished.

Delivery

A release path with a rollback

Clusters on OpenShift, EKS, and AKS only help if a team can ship without a specialist in the room. Helm and Argo CD are that path. Progressive delivery is blue-green or canary, image scanning happens before the rollout, and the service mesh and RBAC are there so production access is deliberate. Jenkins, GitLab CI, and GitHub Actions are the gates. The point is a rollback that does not require me.

  • Kubernetes
  • Argo CD
  • Istio
  • CI/CD
  • Trivy

Reliability

Operated, not just deployed

I stay on the pager. SLIs and error budgets decide what is urgent. Prometheus and Grafana carry the metrics, ELK the logs, OpenTelemetry the traces. AI observability sits on that telemetry: it has to explain the alarm, not add another dashboard. Alarms with a known fix take an autonomous healing path in Harness and remediate themselves. A novel failure still pages me. The write-up afterward changes the module or the alert, so the same page does not come back.

  • AI observability
  • Harness
  • Autonomous remediation
  • SLOs
  • OpenTelemetry

Agentic systems

Agents that have to earn production

I build multi-agent workflows with LangGraph, LangChain, MCPs, and AgentCore. Supervisor–worker, hierarchical, and plan-and-execute are patterns I use when the task actually splits that way. State, memory, and tool calling are designed, not left to the prompt. Retrieval is vector search over enterprise knowledge, and an answer that cannot cite it does not ship. Evaluation, guardrails, and a human gate sit in the same CI/CD path as any other release. Cursor skills and hooks are how that path stays reproducible for the people writing the workflows.

  • LangGraph
  • RAG
  • Guardrails
  • Human in the loop
  • CI/CD
