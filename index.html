About

The same job, at a larger scale.

I came up through Linux and cloud operations, then spent the last several years making delivery repeatable: infrastructure in code, a Kubernetes path people can use, and an on-call loop that feeds back into the design. The agentic work is the same job. A workflow that can call tools and retrieve knowledge still has to be provisioned, released, observed, and stopped.

  1. If it needs a ticket, it is not a platform.

    Engineers should provision, deploy, and roll back without waiting on me. Terraform, pipelines, and GitOps exist so the exception is rare, not so the happy path stays manual.

  2. Autonomy is earned.

    An agent gets tool access and memory after evaluation, guardrails, and a human gate exist. Deterministic release steps stay in charge. The model does not get a private way into production.

  3. Incidents are design input.

    A postmortem that only updates a runbook will happen again. The useful ones change the module, the pipeline, or the alert threshold.

Selected work

Four problems already running in production.

01

Platform

One way to stand an environment up

The problem The estate spans AWS, Azure, and what is still on VMware and OpenStack. Each one had its own way to stand an environment up, and the bootstrap lived in someone’s notes.

What I run Terraform holds the shape of the environment, including remote state and drift. Ansible holds configuration, patching, and that bootstrap. Multi-AZ, recovery, and cost are part of the module, reviewed with the change.

The standard A platform nobody can afford, or that only one person can rebuild, is not finished.

Terraform · Ansible · AWS · Azure · FinOps

02

Delivery

A release path with a rollback

The problem Clusters on OpenShift, EKS, and AKS only help if a team can ship without a specialist in the room.

What I run Helm and Argo CD are that path. Progressive delivery is blue-green or canary. Image scanning happens before the rollout. The service mesh and RBAC keep production access deliberate. Jenkins, GitLab CI, GitHub Actions, and Harness are the gates.

The standard The rollback does not require me.

Kubernetes · Argo CD · Harness · Istio · Trivy

03

Reliability

Operated, not just deployed

The problem A dashboard that does not explain the alarm is another page to ignore. A known failure that still needs a person is toil.

What I run I stay on the pager. SLIs and error budgets decide what is urgent. Prometheus and Grafana carry the metrics, ELK the logs, OpenTelemetry the traces. AI observability sits on that telemetry and has to explain the alarm. Alarms with a known fix take an autonomous healing path in Harness and remediate themselves.

The standard A novel failure still pages me. The write-up afterward changes the module or the alert, so the same page does not come back.

AI observability · Harness · Autonomous remediation · SLOs · OpenTelemetry

04

Agentic systems

Agents that have to earn production

The problem A workflow that can call tools and retrieve knowledge still has to be provisioned, released, observed, and stopped. Left to the prompt, it will not be.

What I run Multi-agent workflows in LangGraph, LangChain, MCPs, and AgentCore. Supervisor–worker, hierarchical, and plan-and-execute when the task actually splits that way. State, memory, and tool calling are designed. Retrieval is vector search over enterprise knowledge, and an answer that cannot cite it does not ship. Evaluation, guardrails, and a human gate sit in the same CI/CD path as any other release. Cursor skills and hooks keep that path reproducible for the people writing the workflows.

The standard The model does not get a private way into production.

LangGraph · RAG · Guardrails · Human in the loop · CI/CD
